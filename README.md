## 🛍️ Zen Mart Pro – Multi‑Vendor E‑Commerce & Delivery Platform

Zen Mart Pro is a full‑stack, multi‑role mobile application built with Flutter for the frontend and Python (Flask) + Firebase for the backend.  
It serves four distinct user types – Admin, Vendor, Rider, and Customer – each with tailored dashboards and workflows.  
The app supports real‑time order management, product inventory, delivery tracking, earnings analytics, and role‑based access control – all powered by Firestore and a secure Python API layer.

## ✨ Features

👤 Customer
- Browse featured shops and popular products.
- Search products (case-insensitive) with real-time Firestore queries.
- Add/remove items from cart; adjust quantities.
- Place orders with delivery address and fee calculation.
- Track order status in real time.

🏪 Vendor
- Manage own shop details and products (CRUD).
- View incoming orders with status filters.
- Update order status (Pending → Preparing → Ready for Pickup).
- Real-time dashboard with revenue, order count, and product stats.

🛵 Rider
- See available deliveries and accept orders.
- Manage active deliveries (status updates: Picked Up, Out for Delivery, Delivered).
- View earnings history and daily earnings chart.
- Filter and view completed deliveries.

🔧 Admin
- Full oversight of users, vendors, shops, orders, and riders.
- Promote/demote user roles (Admin, Vendor, Rider, Customer).
- Analytics dashboard with revenue trends (bar chart) and order metrics.
- Manage all orders and resolve disputes.

🔐 Authentication & Authorization
- Firebase Authentication (email/password).
- Role-based access controlled via Firestore role field.
- Admin API endpoints secured with Firebase Admin SDK.

## 🧱 Architecture Overview

```text
┌─────────────────┐      ┌─────────────────┐      ┌─────────────────┐
│  Flutter App    │ ◄──► │  Firebase Auth  │ ◄──► │  Firestore DB   │
│  (Mobile)       │      │  (User Auth)    │      │  (Real‑time)    │
└────────┬────────┘      └─────────────────┘      └────────┬────────┘
         │                                                  │
         │ (Admin operations)                               │ (Direct client ops)
         ▼                                                  │
┌─────────────────────────────────────────────────────────────────────┐
│                  Python Flask Backend (Admin API)                  │
│  – Secure endpoints for user management, role updates, analytics  │
│  – Uses Firebase Admin SDK (bypasses security rules)              │
└─────────────────────────────────────────────────────────────────────┘
Client SDK: Flutter app reads/writes Firestore directly for most operations (products, cart, orders, etc.).
Admin API: Handles sensitive operations (role changes, user deletion, advanced analytics) – only accessible by authenticated admins.
```

## 🛠️ Tech Stack

Frontend (Flutter)
- Flutter 3.x + Dart
- State Management: Riverpod (providers, state notifiers)
- Firebase: firebase_core, firebase_auth, cloud_firestore
- Charts: fl_chart
- UI: Material 3, custom widgets, Lottie animations
- Push Notifications: firebase_messaging (FCM) – integrated but not fully utilised

Backend (Python Flask)
- Flask web framework
- Firebase Admin SDK (Python)
- PyJWT for token verification
- CORS enabled for mobile communication

Database
- Firestore (NoSQL, real-time) – stores users, products, shops, orders, deliveries.

DevOps
- Firebase Hosting (static assets) / Flask deployed on Render/Railway (or any VPS)
- Environment variables for Firebase credentials and secret keys.


## 🚀 Getting Started

Prerequisites
- Flutter: [Installation guide](https://docs.flutter.dev/get-started/install)
- Python 3.8+ and pip
- Firebase account and a Firebase project (with Authentication, Firestore enabled)
- Android Studio / VS Code (for emulator or physical device)
- Git

Installation – Flutter App

Clone the repository
```bash
git clone https://github.com/yourusername/zen-mart-pro.git
cd zen-mart-pro
```

Install dependencies
```bash
flutter pub get
```

Configure Firebase
- Create a Firebase project.
- Enable Email/Password authentication.
- Download google-services.json (Android) and/or GoogleService-Info.plist (iOS).
- Place them in the android/app/ and ios/Runner/ directories respectively.
- Copy firebase_options.dart (generated by flutterfire configure) into lib/.

Run the app
```bash
flutter run
```

Backend Setup (Python Flask)

Navigate to the backend folder
```bash
cd backend
```

Create a virtual environment
```bash
python -m venv venv
source venv/bin/activate   # On Windows: venv\Scripts\activate
```

Install dependencies
```bash
pip install -r requirements.txt
```

Add Firebase Admin SDK credentials
- Generate a private key from your Firebase project (Project Settings → Service Accounts → Generate New Private Key).
- Save it as firebase-key.json in the backend folder.
- IMPORTANT: Never commit this file to version control – add it to .gitignore.

Set environment variables
Create a .env file (or set them directly):
```bash
FLASK_APP=main.py
FLASK_ENV=development
FIREBASE_KEY_PATH=./firebase-key.json
SECRET_KEY=your-secret-key-for-jwt
```

Or export them:
```bash
export FIREBASE_KEY_PATH=./firebase-key.json
export SECRET_KEY=your-secret-key
```

Run the Flask server
```bash
python main.py
```

The API will be available at http://localhost:8000.

Firebase Configuration

Authentication
- Enable Email/Password sign-in method.

Firestore
- Create the following collections (with security rules – see below):

users – fields: uid, email, displayName, role, shopId, riderId, createdAt  
shops – fields: name, address, rating, shopId  
products – fields: name, nameLower, price, stock, shopId  
orders – fields: customerId, shopId, items[], subtotal, deliveryFee, total, vendorAmount, riderAmount, status, deliveryAddress, createdAt, updatedAt  

Security Rules: Example (minimal):
```text
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{document=**} {
      allow read, write: if request.auth != null;
    }
  }
}
```

(For production, restrict more – only allow users to read/write their own data.)

## 📡 API Endpoints (Python Backend)

The backend exposes these endpoints (all prefixed /api):

Auth

Method | Endpoint | Description
--- | --- | ---
POST | /auth/signup | Register a new user (returns user data)
POST | /auth/signin | Sign in (returns Firebase ID token)
POST | /auth/verify-token | Verify a Firebase ID token
GET | /auth/me | Get current user info (with role)
POST | /auth/signout | Sign out (client-side)

Admin (Protected – requires admin role)

Method | Endpoint | Description
--- | --- | ---
GET | /admin/dashboard | Admin overview stats
GET | /admin/users | List all users
PUT | /admin/users/{user_id}/role | Update a user’s role
DELETE | /admin/users/{user_id} | Delete a user
GET | /admin/stats | Global stats (orders, revenue, etc.)

Authentication: All admin endpoints require a valid Firebase ID token in the Authorization: Bearer <token> header. The backend verifies the token and checks the user’s role in Firestore before processing.

## 🔐 Environment Variables

Flutter (lib/firebase_options.dart)
- Generated by flutterfire configure – contains Firebase project IDs and credentials.

Backend (.env or shell)
- FIREBASE_KEY_PATH – path to the Firebase Admin SDK JSON key.
- SECRET_KEY – a secret for signing JWTs (optional for token verification).
- PORT – default 5000.

## 🚀 Deployment

Flutter App
- Android: Build an APK or App Bundle:
```bash
flutter build apk --release
```
- iOS: Build with Xcode.

Backend (Flask)
- Deploy to Render, Railway, Heroku, or any VPS.
- Make sure to set environment variables.
- For production, use a production WSGI server (e.g., Gunicorn).

Firebase Firestore
- Set up production security rules.
- Consider enabling Firestore indexes for advanced queries (e.g., search by nameLower).
